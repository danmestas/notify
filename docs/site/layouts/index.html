One event in, every channel out

Your app sends one event. The workflow decides who hears about it, where, and when.

# your app, once
curl -X POST https://notify.example.com/v1/events/trigger \
  -H "Authorization: ApiKey $KEY" \
  -d '{
    "name": "invoice-paid",
    "to": { "subscriberId": "dan" },
    "payload": { "amount": "$480.00", "invoice": "INV-2291" }
  }'

# every /v1 response carries
Notify-Contract: 1

The API only grows: /v1 changes are additive.

  1. Deliver in the appThe subscriber's inbox and live feed update first. in_app
  2. Send the emailWith a tokenized reply address, so an answer threads back. email
  3. Keep it politeA throttle caps how often one person hears from you. throttle
  4. Roll it upSimilar events wait and go out together on the subscriber's schedule. digest
  5. Wait for the right hourDelays run in the subscriber's own timezone. delay

What it handles

The parts every product rebuilds, in one service you run yourself.

Channels
In-app, email, SMS, push and chat, with per-subscriber preferences, templates, layouts and translations. Provider adapters are optional, so you can start with your own SMTP.
Timing
Delays, digests, throttles and schedules that the engine holds durably, in each subscriber's timezone.
Inbox and agents
A subscriber inbox and conversations with agents. A managed agent runs on its owner's model, from any provider, with a key that is sealed and never returned.
Inbound mail
Replies come back in. notify receives mail over SMTP or a webhook, drafts answers for review, and keeps every original byte for byte.
Operations
One Go binary, SQLite, and blobs on disk or any S3 store such as Garage. A console for workflows, subscribers and deliveries.

Runs on

No hosted dependency in the delivery path.

  • dagnats durable workflow engine
  • NATS messaging
  • SQLite records
  • Garage or any S3 original mail
